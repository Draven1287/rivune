# Traycer integration discovery

Reviewed September 8, 2026. Read-only official documentation and public source inspection; no CLI execution, account access, provider calls, installs, builds or UI attachment. Feasibility evidence only. Source pinned to `0615e8ed65239615d8aab474fd6bc3a9be1f0a5f`; this main-branch snapshot is not proof a released/installed Host supports every method.

## Recommended boundary

A version-pinned CLI adapter to an existing, explicitly selected Traycer Task and eligible local agent is plausible. Automatic resumable/exactly-once handoff is **not established**. Preserve an unknown-outcome state and require reconciliation rather than blindly resending. Keep R3 HOLD intact; earlier local hashes prove current identity, not contemporaneous full-source closure/native acceptance.

The [official CLI](https://docs.traycer.ai/cli/commands) exposes workspace listing, child-agent creation, send/transcript/inbox/monitor, Task and sender IDs, and machine-readable output where supported. `--no-bootstrap` prevents automatic bootstrap behavior according to the docs. No top-level new-Task command is documented there: `agent create` creates a child. New-Task creation remains unresolved and outside the proposed first adapter.

## Duplicate sends and retries

The send request has no client operation/idempotency key. Pending-thread registration is described as idempotent per sender→receiver pair; that does **not** establish deduplicated prompt execution. [`host-rpc.ts:245`](https://github.com/traycerai/traycer/blob/0615e8ed65239615d8aab474fd6bc3a9be1f0a5f/clients/traycer-cli/src/internal/host-rpc.ts#L245) passes `idempotencyKey: null`. The [retry wrapper](https://github.com/traycerai/traycer/blob/0615e8ed65239615d8aab474fd6bc3a9be1f0a5f/clients/shared/host-transport/retrying-messenger.ts#L57) retries only classified safe failures; ambiguous unkeyed post-send failures propagate. A new CLI invocation after uncertainty is a new call, not a proven replay-safe retry.

Therefore save intent locally before dispatch, retain acknowledged IDs, and stop automatic retries on ambiguous outcomes. A Rivune correlation marker can aid reconciliation but cannot itself provide receiver-side deduplication. Safe automatic resume still requires release-specific tests or a supported host contract for duplicate execution, final-reply correlation, restart persistence and stop races. Do not call this exactly-once delivery.

## Access, costs and other interfaces

- [Hosts](https://docs.traycer.ai/concepts/hosts): sending requires the same Host; transcript access depends on user/surface/Host. Check returned capabilities, not just agent visibility.
- [CLI README](https://github.com/traycerai/traycer/blob/0615e8ed65239615d8aab474fd6bc3a9be1f0a5f/clients/traycer-cli/README.md): browser OAuth PKCE, shared Desktop auth and separate signed Host. Host ensure can install/register/start services; no silent setup or credential copying.
- [Pricing](https://docs.traycer.ai/account/pricing): BYOA is $0/local-only without sync/sharing/Traycer credits; Sync is $10/user/month. Other agents retain their own account/API billing. Traycer inference uses upstream pricing plus 20%. No account entitlement or quota was inspected.
- [Protocol](https://github.com/traycerai/traycer/blob/0615e8ed65239615d8aab474fd6bc3a9be1f0a5f/protocol/README.md): per-method negotiated Host RPC, not evidence of a stable public REST service. [Extension MCP](https://docs.traycer.ai/extension/integrations/mcp) is Traycer consuming remote tools, not an exposed Traycer MCP server. [Custom CLI agents](https://docs.traycer.ai/extension/integrations/custom-cli-agents) support reverse-direction prompt handoff, without proving a returned-result API.
- [MIT license](https://github.com/traycerai/traycer/blob/0615e8ed65239615d8aab474fd6bc3a9be1f0a5f/LICENSE) covers public repository code with notice retention. [Repository boundary](https://github.com/traycerai/traycer/blob/0615e8ed65239615d8aab474fd6bc3a9be1f0a5f/AGENTS.md): Host/cloud backends are absent; do not extend that license assumption to them.
