# Rivune Tauri R2 — setup and chat parity review

Date: 2026-09-08  
Scope: read-only source and existing-evidence comparison. No build, UI launch, provider call, canonical-source edit, or new mockup was performed for this review.

## Verdict

The current Tauri R2 is **not yet a feature-parity replacement** for the earlier SwiftUI app. It is a smaller, safer direct-chat foundation. It preserves local conversations, per-conversation drafts, one selected CLI connection, direct submission, cancellation, retry, reconciliation, and read-only legacy import. It regresses or omits the earlier app's structured model/reasoning controls, CLI-or-API setup, searchable and organized conversation history, attachments/project workflow, and runnable multi-model collaboration.

This is not a recommendation to revert to SwiftUI. The right direction is to keep Tauri's stronger admission, persistence, shutdown, and retry invariants, then restore the missing product behaviors on top of them.

## Evidence boundary

- **Earlier SwiftUI source behavior** means the current Swift files contain the implementation. It is not automatically proof that a user exercised that behavior successfully.
- **Earlier SwiftUI verified behavior** is limited to retained receipts. The accepted native Settings build recorded 278 passing tests, a universal Release build, installed-app inspection, Settings draft/focus preservation, 24 restored conversations, and provider discovery showing Codex/Claude ready plus Gemini/Ollama as adapter-needed. It explicitly did **not** prove live generation or arbitrary CLI support: `qa-artifacts/native-settings-20260906/build-0619/REVIEW.md` and `test-summary.json`.
- **Tauri source behavior** means the canonical R2 source exposes the path described below.
- **Tauri verified behavior** is limited to existing frozen evidence. `R2_SOURCE_FREEZE.md:31-42` records an offline Rust build, 14 renderer/core/wire tests, 47 synthetic-host Chromium checks, and focus/draft harnesses, while explicitly saying the exact source freeze still needed a current real-WebView native proof. No new verification was run here.

## Highest-impact restoration jobs

### 1. Restore catalog-driven provider, model, and reasoning setup

Build one end-to-end vertical slice that replaces the hard-coded Codex/Claude radio buttons and free-text model override with host-returned provider registrations and capabilities. Each registration must keep installation, authentication, tested response, transport (CLI/API), model availability, reasoning availability, and runtime-adapter support distinct. The UI must render only enforceable choices, preserve provider defaults, and tolerate a newly discovered model without a Rivune release. API secrets must remain in OS credential storage and never enter workspace snapshots.

Acceptance: a fixture catalog with at least four providers and mixed CLI/API transports renders dynamically; an unsupported discovered CLI is labelled adapter-needed rather than runnable; model/effort choices are validated at admission; no provider call occurs during discovery; existing direct-chat, draft, retry, and shutdown tests remain green.

### 2. Restore the conversation workspace without weakening draft safety

Extend the persisted conversation schema and host commands for search metadata, rename, favorite, archive/restore, delete, and project placement. Add the clean sidebar controls only after persistence/migration rules exist. Preserve Tauri's current per-conversation serialized draft writes, navigation revision guards, active-conversation persistence, failed-save recovery, and shutdown flush. Add rich draft fields for explicitly selected attachments/artifacts/project context as separate approved channels; never flatten them into prompt text.

Acceptance: search covers title, project, user messages, and answers; every organization action survives restart; delete is explicit and recoverable or clearly irreversible; two-conversation rapid navigation cannot cross-contaminate drafts; Settings and all sidebar actions preserve focus and unsent rich draft state; imported history remains inert/read-only unless a separate reviewed "continue as new" action is added.

### 3. Wire Constellation as a real strategy behind the same admission ledger

Do not add another decorative mode card. Introduce a host-owned team run record that freezes the selected participants, routes, model/effort selections, approved context channels, task split, appointed lead, independent outputs, cross-reviews, final synthesis, and retry ancestry before execution. Direct and Constellation runs should share request identity, persistence, cancellation, uncertainty reconciliation, shutdown, and renderer conventions. Show the final answer first; place plan, contributions, and reviews in a readable collapsible inspection surface.

Acceptance: at least two independently admitted provider contributions are required before synthesis; each participant receives its own scoped task plus the shared brief; cross-review is recorded before the lead resolves; a partial failure never masquerades as completion; retry reuses the exact frozen context and successful retained work without duplicate provider calls; the UI clearly distinguishes planned, running, partial, failed, and complete; deterministic fixtures prove the workflow before any usage-consuming evaluation.

## Directional conclusion

Keep Tauri as the replacement direction, but stop judging it as complete because the shell launches or direct chat works. The next credible milestone is **Tauri R3 feature parity for setup + conversation workspace**, followed by **Constellation execution parity**. Visual polish should follow these product contracts, not conceal their absence.
