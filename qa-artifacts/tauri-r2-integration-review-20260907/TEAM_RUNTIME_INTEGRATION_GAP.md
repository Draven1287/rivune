# Real team runtime integration gap

Read-only observation, September 8. SOURCE hashes in TEAM_RUNTIME_INTEGRATION_GAP.json bind the files read; runtime owns integration and may change them. This is not a frozen-current or native acceptance claim. No source changes, builds, provider calls or UI actions.

## Implemented path versus module behavior

web/app.mjs submission constructs mode="direct". host.rs SubmitRunRequest carries id/conversationID/prompt/mode. prepare_submission selects one configured provider and assembles approved history; imported conversations are refused. submit_run invokes HostState::execute on a blocking worker. execute rejects any non-direct mode, validates provider/context, persists admission under the lifecycle barrier, registers cancellation, calls run_direct, then finish_execution persists terminal output and removes cancellation ownership. Failed/uncertain persistence has reconciliation handling. cancel_run sets the one request flag; retry_run clones the original admission under a new explicit ID. These are actual wired Single AI source paths, not proof that real providers were tested here.

team_strategy.rs is exported by lib.rs but has no host dispatch consumer in the observed files. Session contains frozen membership/lead, decision proposal validation, scoped task scheduling, concurrency, contributions, integration/review delivery and checkpoint/restore. new_with_concurrency/next_invocations/mark_batch_dispatched and outcomes are module behavior. Passing these tests does not make Constellation executable in the app.

## Five prioritized integration gaps

1. **P1 — Admit a real frozen team.** Extend host.rs SubmitRunRequest/prepare_submission and persisted RunRecord/WorkspaceSnapshot with a versioned team admission (or explicit tagged run variant). Resolve selected lead/member IDs against configured provider/model capabilities and explicit permissions, producing team_strategy::FrozenRun. Keep automatic strategy as a lead decision; manual override is optional. Never infer strongest model from a label or silently replace an unavailable member. Bridge DTO and app.mjs composer selection must send this intent. Tests: selected team changes after admission cannot alter it; stale provider/model rejected; imported history cannot run; same request ID with different team rejected; budget and scope cannot be enlarged by model text. Existing direct mode remains working.

2. **P1 — Drive the engine through actual adapters.** HostState::execute currently calls run_direct once. Add a team branch that creates Session::new_with_concurrency, gets next_invocations, validates executable/model capability for each invocation, calls mark_batch_dispatched, durably saves its checkpoint, then launches bounded adapter workers. Translate role/instruction/context/contributions into provider input without flattening reference text into authority. The lead's Decide output must pass LeadProposal validation before workers launch. run_direct/provider_arguments currently serve one isolated direct request; reuse only supported adapter behavior. Swarm scope grants require host-enforced working directories/file/tool boundaries; the module's strings alone are not enforcement. Tests: Council drafts do not see siblings; independent workers overlap; same-scope tasks serialize; dependencies see only permitted predecessor outputs; malformed decision or unsupported capability launches no work; failed checkpoint means no child starts.

3. **P1 — Persist and recover every invocation.** Store Session::checkpoint with the durable parent run, revision and bindings; load via Session::restore in host recovery. Existing save/persist_with_fault generations and uncertain-admission handling should remain authoritative. Each record_outcome must be saved before further scheduling or declaring delivery; reconciliation must preserve completed sibling results. Tests: crash after dispatch restores uncertain work without replay; outcome-save failure retains recoverable result; stale/duplicate/out-of-order callbacks cannot overwrite another member; retry_failed creates only intended retry within the frozen budget; version-1 workspace/history remains readable after schema extension.

4. **P1 — Cancel and shut down the whole team.** Extend HostLifecycle cancellations, cancel_run, shutdown handling and terminate_owned_process_tree to track all child invocation ownership under the parent request. Session::cancel halts scheduling but does not itself terminate processes. Drain/reap every owned worker, persist terminal cancellation and preserve late outputs as receipts without resurrecting a run. Tests: Stop during parallel workers cancels all; no new worker starts after cancellation; quit waits for terminal persistence; one child exit failure cannot orphan another; repeated cancel/quit is idempotent; save failure keeps recovery visible rather than claiming clean completion.

5. **P1 — Deliver one integrated, reviewed result with honest progress.** Convert Session::delivery into the parent run's final answer only after required integration/review and durable terminal save. Keep per-member contributions as expandable evidence in snapshot DTO/core.mjs/transcript UI, not competing final chat messages. For artifacts, host independently hashes staged files and verifies ArtifactReceipt/review digest; model claims are insufficient and delivery does not imply files applied. Add selected lead/team and current phase to the real composer/status; preserve draft/retry/navigation behavior. Tests: one final result after Council and Swarm; worker draft never mislabeled final; failed review shows blocked state; changed artifact digest prevents delivery; final save failure offers reconciliation; restart preserves final answer and evidence; follow-up history contains the delivered result without duplicating all drafts.

## Smallest integrated slice and acceptance

Implement a vertical path across existing host admission/storage/dispatch, bridge snapshot and composer/transcript. Use the existing engine rather than another standalone module. First drive automatic lead choice and Council plus scoped Swarm through deterministic executable fixtures to prove orchestration, cancellation, restart and one final result. Then run authorized real supported provider tasks (one Council question and one Swarm artifact project) in the built app, inspect outputs and artifacts independently, and compare a Single AI baseline. Fixture success is not provider parity; CLI availability is not consumer ChatGPT/Claude interface feature equivalence. Keep Constellation unavailable until that actual path exists. This ordering preserves the full requested product rather than treating a direct-only release as its completion.
