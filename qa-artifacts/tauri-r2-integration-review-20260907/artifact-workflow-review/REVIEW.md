# Artifact workflow bounded contract review

Two P2 contract findings. Proposed behavior only; no implementation/native acceptance.

1. **Prepared diff cannot retrieve its original bytes.** CONTRACT step 3 requires a reviewable diff with exact baseline contents. PreparedApply exposes hashes and counts only; readArtifactFile retrieves proposed artifact content, while no command returns captured original content or a host-generated diff bound to preparedOperationId. FIXTURE.json's replaced index.html has materially different original text, which cannot be reconstructed from its hash/size. Add a bounded operation-scoped diff/original-content read (or diff payload) bound to the prepared immutable baseline and replacement hashes. It must read captured private preparation data, not reread changing disk or accept renderer paths. Add a replace-file case proving the displayed removed/added text matches those captured bytes and stale preparation cannot apply.

2. **Draft/receipt persistence failure conflates precommit and postcommit outcomes.** CONTRACT says failed draft/receipt saves preserve prior state; draft-save-failure expects old saved state for an unspecified fault. Existing host commit_candidate publishes a candidate when a save fails after rename, returning crash-durability uncertainty. Split precommit unchanged, postcommit visible/uncertain, and durable success/lost response, as already resolved in R4. Extend continuation outcome/error DTOs to expose authoritative visible revision/mutation and unresolved durability, retaining local edits without claiming rollback. Block dependent Send/Apply success/Quit until durable reconciliation; readback alone is insufficient. Add phase-specific continuation/receipt cases and immutable same-ID recovery, including late acknowledgements versus newer rich-draft selection.

Other reviewed boundaries are coherent at contract level: immutable origin hashes; active owner/project/root grant revalidation; no inherited archive permissions; no-follow path handling and aliases; journal/backups before project writes; guarded rollback/revert; exact continuation selection with draft CAS; no automatic execution/preview authority. These still require concrete runtime implementation, platform behavior and fault tests. Existing draft-revision/root-grant type mapping is explicitly a future runtime acceptance dependency.

Independently checked the synthetic raw response hash, both content lengths/hashes, exact revision hash encoding/vector, and 26 case definitions. RECEIPT.json binds the five reviewed files. These are fixture-integrity checks only, not apply/revert/restart tests. No canonical edits, project-file writes, UI, build, provider or account actions occurred.
