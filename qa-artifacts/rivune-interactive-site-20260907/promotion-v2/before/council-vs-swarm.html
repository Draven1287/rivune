A guide to Rivune

Council vs. Swarm

One Mac app, one proposed AI team. Rivune is being developed to suggest eligible members and a manager, then coordinate independent answers or delegated work from one prompt.

Council: First development stage.
Swarm and Auto: Future milestones.

The public source preview 4 predates the configurable team experience. This guide explains the project direction, not features you can install from that source release.

Council: independent answers, then a manager

Council is intended for questions that benefit from different perspectives: comparing approaches, weighing a decision, or reviewing a proposed solution.

The planned Council workflow gives team members the same approved task context. They answer independently, without seeing each other’s drafts. The manager then reviews their contributions and writes one final answer. It can combine, correct, or reject claims; unresolved disagreement should remain visible.

Who chooses the team and manager?

Rivune should propose an eligible team and manager so you can start without a setup exercise. You can keep that suggestion or choose members, models, and supported reasoning settings beside the prompt. Multiple members may use the same provider tool with different settings. The reusable team is editable; a running task retains the configuration it started with.

A suggested manager reflects supported capabilities and your preferences, not a proven intelligence ranking. Rivune does not assume a universally smartest provider. The planned run record identifies the selected manager and any explicitly allowed replacement after failure; otherwise the task stops with completed work retained. Team size and whether the manager also drafts independently are implementation choices to evaluate, not requirements to install another model.

Swarm: agents own different parts

Swarm is intended for projects with separable work. The manager assigns concrete tasks to real workers, permits supported bounded delegation, then coordinates review and integration.

For a small website, tasks might cover content, layout, and checks. Each worker needs an owner, a scoped workspace, and a record of its changes. Work can run in parallel when dependencies and file ownership permit it. Overlapping changes must be resolved during integration.

The planned result includes usable files and actual check results, with agent activity available to inspect. A transcript that merely describes agents is not evidence of worker execution.

Which mode fits your task?

  • Council: you need a considered answer to one question, informed by independent responses.
  • Swarm: you need separate agent tasks to produce and integrate parts of a project.
  • A single-provider chat: a straightforward question may not need a collaboration workflow.

Automatic workflow selection is a later milestone, after both execution paths qualify. Manual choice remains available where supported. Council-only development is a temporary stage, not the final product scope.

These are intended uses, not measured performance claims. Rivune has not established that Council or Swarm is more accurate or useful than a single model. That requires recorded comparisons on real tasks.

What is available now?

The public source release is preview 4, a developer ZIP requiring Xcode. It predates the configurable team and manager. Council is the first stage of current development; real Swarm and Auto remain future milestones. Local builds and private checks are not a public release. Earlier Together conversations retain their original history and must not be relabeled as the new workflows.

The current source preview is for developers and requires Xcode to build. Check the current Mac installer availability and release status before downloading anything.

Providers, accounts, and access

The initial foundation uses the supported Codex CLI and Claude Code CLI connections. You need the relevant installed tool, provider sign-in, and permission to use your chosen model. Provider terms, limits, and charges apply separately; a free account may not include the access you need.

Planned Council runs require at least two successful independent participants for a completed multi-model result. Swarm also requires verified worker support in the participating adapters. Installing a CLI does not by itself enable either mode or prove that it can delegate agents.

Local history, provider processing

Rivune stores conversation history locally by default. AI requests still go to connected providers. Council’s planned manager receives the participating models’ successful answers; Swarm’s workers receive the approved context needed for their assigned tasks.

Review what you include in prompts, context, and attachments. Provider processing and retention follow the applicable provider terms. Read privacy and data sharing for the current behavior and the planned modes’ boundaries.
