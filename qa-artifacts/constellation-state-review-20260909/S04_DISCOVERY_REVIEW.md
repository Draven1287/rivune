If the discovery command is delayed before `begin`, cancellation misses it and subsequent registration proceeds. Independently reproduced the frontend half with a synthetic delayed bridge: cancellation returned false, the frontend returned cancelled, then the fake native request registered with no second cancellation. The native session deadline remains fallback, but starts after spawn/setup. Fix with bounded cancellation tombstones or an acknowledged registration/cancellation protocol, and distinguish discarded frontend results from confirmed process termination. This is already disclosed in the receipt, not a newly discovered regression.

2. **P2 — Cleanup completion is unobservable and not independently bounded.** `Process::drop` ignores group-kill, child-kill, wait and scratch-removal errors. A successfully parsed report can consequently remain successful despite failed scratch cleanup; a stalled wait holds the global discovery and host operation leases beyond the session deadline. Frontend timeout only discards the result and requests cancellation. Refactor explicit cleanup to report its outcome and define bounded escalation before claiming completed cancellation. Current documentation accurately acknowledges this gap. Source finding only: no cleanup fault injection or native execution performed.
