ProviderSetup initializes persistent recovery in checking state, blocking setup. Its mount effect calls only read; no reserve, apply, reconcile, acknowledge or route inspection runs automatically. A retained reserved/applied/rejected operation becomes uncertain, including visible applied state. Read failure also blocks setup. Repeated mount cannot replay apply through this code. Only explicit configure reserves then applies; only explicit recovery invokes reconcile/acknowledge. The component remains mounted when its dialog closes.

All five own data-method capabilities are required. Missing/accessor methods cannot activate persistent recovery. Partial capability falls back to the existing explicitly guarded volatile adapter only if that adapter exists, with the visible restart-recovery warning; there is no unguarded configureProvider fallback. Bridge operationId arguments match native operation_id command parameters; the new commands are registered. The legacy native configuration entrypoint rejects unacknowledged operation records, which is the required native fence when a renderer lacks the full capability.

The adapter retains private prepared intent and passes detached copies for reserve/apply. Parsed operation copies isolate reply data. Apply replies and terminal acknowledgements must match operation ID, every intent field, exact expected state and acknowledged bit. Durable configure return occurs only after applied plus terminal acknowledgement; mismatched/lost/rejected replies remain uncertain. Lost reservation has no automatic apply retry; explicit reconciliation reads its host record and expects reserved to become rejected. Applied state requires explicit durable reconciliation/acknowledgement, without apply. A stale read racing another transition fails closed on state/identity mismatch and can be explicitly checked again.

A null outstanding read means none, not a receipt that configuration succeeded. UI clears the outstanding-operation fence with wording that no record is present, rather than promoting snapshot equality to durable. Rejected recovery does not claim a connection was saved; its display-refresh context stays generic. Prior durable display-refresh separation remains present.

In-flight configure/reconcile share an adapter busy fence; component busy/state fences prevent replacement while uncertain/checking. After uncertainty the adapter itself releases busy, so recovery-before-another-attempt depends on ProviderSetup plus the host's unacknowledged-record fence, not a standalone durable browser lock. Read is intentionally not serialized by the adapter, but it performs no mutation. The component disables setup for existing workspace work through its parent props. This is not a new global controller operation lock, and there remains no timeout/cancellation for permanently pending promises. Configuration intent includes no conversation, draft, attachment bytes, prompt or auth data; refresh retains dirty local drafts under existing controller behavior.
