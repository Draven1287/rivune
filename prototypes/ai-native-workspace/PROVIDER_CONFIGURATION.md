# Explicit discovered-route configuration contract

This optional contract prepares a route the user explicitly chose from an existing host discovery result. It does not discover routes on mount, configure automatically, sign in, probe an account/model, or submit a message. Settings now exposes separate explicit Find installed providers and Save as workspace default actions. Unsupported optional bridges show an explanation, with no legacy fallback.

`createProviderConfigurationAdapter` requires the optional `configureSelectedProvider` bridge method. Legacy bridges return unavailable; the adapter never falls back to unguarded configuration. `prepareProviderConfiguration(route,snapshot,select)` accepts installed Codex/Claude route identities only, provider default only, and captures the expected current provider configuration and global selection. A contradictory existing identity/model requires separate review. Input snapshots and drafts are not changed. Concurrent adapter calls are rejected.

The bridge invokes existing `configure_provider` with an optional schema-v1 guard. Legacy callers without a guard retain their prior behavior and null acknowledgement. Under the existing mutation/workspace locks, guarded configuration rechecks the selected route against local executable search results and its canonical-path discovery ID. This is filesystem inspection only, not executing a provider. It rejects stale route, saved provider or global selection before mutation. Canonical identity is a path identity, not a binary-content hash; executable replacement at the same path or post-check filesystem changes remain outside this guarantee.

The host commits a cloned snapshot and returns `{schemaVersion:1,state:'durable',provider,selectedProviderID}` only after the existing persistence routine succeeds. Conversations, rich drafts and pending work are copied unchanged. Selecting a global provider does not rewrite an existing conversation's pinned selection or team. Legacy saved provider IDs that differ from discovery IDs are not silently migrated.

The frontend snapshots private expected provider/selection values and passes detached provider and nested guard copies to the bridge. It verifies every acknowledged provider field and selected ID against those private values. Missing, malformed, mismatched or rejected/lost replies return `uncertain / CONFIGURATION_OUTCOME_UNCONFIRMED`; no raw error is exposed and no automatic replay occurs. This contract has no mutation-ID reconciliation and no frontend timeout. Settings fences another attempt until Check saved configuration reads a fresh snapshot, followed by the explicit Review routes for a new save action. Snapshot equality confirms visible state only; the earlier save remains labelled crash-durability-unconfirmed until a new durable acknowledgement. No save is automatically replayed. Pending/uncertain UI state survives closing Settings while this workspace is mounted, but has no durable journal across renderer restart. A indefinitely pending configuration Promise continues to block this mounted picker. Never claim configuration success from request completion alone, or authentication/inference readiness from configuration success.

Synthetic validation covers success, native persisted reopen, injected persistence failure, stale expected route/selection/provider rejection, adapter acknowledgement mismatch/lost reply and unchanged drafts. No real route was configured, no provider process launched and no authentication or inference was exercised.
