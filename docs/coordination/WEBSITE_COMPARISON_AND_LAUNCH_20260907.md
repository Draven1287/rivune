## Design decisions dispatched to the website implementer

1. Product proof earlier: shorten the hero and move the authentic screenshot to a wider showcase directly beneath it. Current split layout and generous separation delay the strongest evidence and make the screenshot smaller.
2. Explain value before mechanics: use brief decision/everyday-work examples, plainly labeled illustrative intended uses. Do not manufacture run results, endorsements or comparative quality claims.
3. Preserve one app with an appointed lead. Council is only in later local development; Auto and real Swarm are still future public features. Keep these availability distinctions visible, with concise wording.
4. Add Aarav's developer introduction, using his actual supplied age/location and no further personal details. A private mailbox was not supplied. Retain the working, explicitly labeled GitHub support route until an actual forwarding alias is configured and verified. Do not ship a fake contact control.
5. Add a short visible FAQ covering current availability, provider access, separate AI usage and local/provider data boundaries. Improve descriptive metadata without promising rankings or AI recommendations.

Implementation goes into a new isolated v4 candidate. V3 remains frozen. Acceptance requires a reproducible patch, source/dist hashes, desktop/390/320 rendering, keyboard/menu/image enlargement checks and accurate download states. The approved native screenshot remains a labeled development preview, not a representation of a publicly downloadable current app.
