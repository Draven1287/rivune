## Compatibility judgment

Inference, not tested integration: either tool can supply visual references or reusable frontend pieces, but generated web code does not supply Rivune's Rust host, durable-result identities, permissions or provider execution. Figma asset/CSS inspection is not a full React application export. A Lovable SSR/backend-dependent project needs adaptation before use in the existing desktop frontend. Keep accepted host contracts and source ownership intact; import selected presentation work only after builder review. No native Tauri compatibility was established by these vendor docs.

## Next action and boundaries

Builder should first confirm whether the existing Claude Design session can produce the needed reviewable screen/prototype within included usage. If it can, continue there without adding Figma or Lovable. If not, name the concrete missing capability before selecting a fallback: Figma for visual composition/handoff; Lovable only for a deliberately separate web prototype whose source portability justifies the extra workflow.
