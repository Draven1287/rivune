# Rivune design reference review

Reviewed September 6, 2026 (America/Denver). Recommendation only; no product or Pages source changes.

The highest-value changes are a clearer composer and quieter result presentation. Rivune already has team editing, a separate final answer, and usable artifact cards in the supplied evidence. Improve those foundations while preserving its silver identity, native Mac window, and everyday-work audience.

## Five prioritized opportunities

### 1. P1 — Make the next prompt the dominant action

**Reference:** Traycer's demo places a prompt beside compact workflow and context controls. [Source](https://traycer.ai/)

**Rivune evidence:** The 0618 home separates workflow/provider options, Team count, a small orchestrator label, composer controls, and connection guidance across several rows. The Team sheet already promotes orchestrator selection; rebuilding that sheet would duplicate delivered work.

**Adaptation:** Keep one prompt and a concise adjacent row for the available workflow, Manager, and Team. Identify the manager with its useful model label and supported effort, with full configuration one action away. Keep the suggested team ready to use when eligible; put a specific connection action beside an unavailable choice. Preserve the currently supported workflow rather than enabling an unfinished path.

**Benefit and acceptance:** A first-time user can identify who will manage the response, change that choice, and send without visiting Settings. At the supported minimum window size, prompt, manager, team, and Send remain readable and keyboard reachable. Sending records exactly the configuration displayed.

### 2. P1 — Keep review evidence accessible without competing with the answer

**Reference:** The public demo compresses command activity into short activity labels within the conversation. [Source](https://traycer.ai/)

**Rivune evidence:** The 0617 fixture already gives the final answer its own card, followed by extensive synthesis, repair, and transport details. The 0613 artifact result demonstrates a more compact collaboration disclosure. This is a consistency opportunity, not a confirmed current regression.

**Adaptation:** Retain the answer first, then one concise outcome line and an expandable review receipt. Put exact member identities, failures, retries, and formatting checks inside that receipt. Keep a material unresolved failure visible. Show observed actions and results rather than simulated progress or private reasoning.

**Benefit and acceptance:** Users can read and copy the answer without expanding diagnostics, while reviewers can find the actual contributors and limitations in one disclosure. A formatting repair never appears as factual verification. Check success, partial failure, cancellation, and retained history in the native app.

### 3. P1 — Make deliverables easy to retrieve after the conversation moves on

**Reference:** Traycer's public demo separates conversations from named artifacts and task statuses. [Source](https://traycer.ai/)

**Rivune evidence:** The 0613 result already has a file count, filenames, Preview, and a save workflow. The screenshot supports keeping this card rather than introducing another output format; it does not establish current project-wide artifact retrieval.

**Adaptation:** Start with a compact “Files from this conversation” entry that opens the existing artifact cards. If already available, improve its placement instead. Show the originating turn and distinguish proposed output, saved output, and subsequent changes using recorded state. Consider a project collection only after conversation retrieval is proven useful.

**Benefit and acceptance:** A user returning to an older conversation can find its exact files without searching through long responses. Switching between two outputs and restarting preserves the correct filenames, content, and save status. Preview remains available before a write.

### 4. P2 — Expose the context that will accompany a request

**Reference:** The demo includes mention-based context and a selected workspace near its composer. [Source](https://traycer.ai/)

**Rivune evidence:** The inspected composers expose attachment controls; the 0613 footer reports no attachments. These views do not establish how a populated context selection behaves.

**Adaptation:** When context is selected, show removable file/project chips with a short scope summary beside the prompt. Expand to inspect what is included. Keep this independent from team configuration. Display usage only if a supported interface reports its real scope and timestamp.

**Benefit and acceptance:** Users can explain what they are sending and remove an item with keyboard or pointer. Switching conversations cannot silently retain another conversation's selection; the recorded request retains its original context after later edits. Inspect the current populated state before deciding a code change is necessary.

### 5. P2 — Demonstrate one complete everyday outcome

**Reference:** Traycer's public page connects a concrete user brief to named output and scoped work. [Source](https://traycer.ai/)

**Rivune evidence:** Home offers Think, Build, and Review starters. The frozen Pages hero communicates the team proposition and installer status but the inspected hero views do not show an actual task outcome.

**Adaptation:** Develop one original, short example such as comparing two plans from supplied notes and producing a decision brief. A starter fills an editable prompt; it does not auto-submit. After an actual accepted run, use an approved native screenshot and concise outcome caption as a future Pages proposal. Label the build and demonstrated workflow, and keep planned features and installer availability accurate.

**Benefit and acceptance:** A new visitor can say what Rivune helps them finish. The example's exact input and saved result are reproducible; any website image depicts the real Mac app and has readable alternative text. This proposal waits until the frozen Pages handoff is explicitly reopened.

## Handoff

Start with opportunities 1 and 2 during native integration, inspect existing populated states before adding controls, and evaluate 3 next. Preserve real Apple window controls and dialogs, Rivune's original branding, and the accepted architecture. This review makes no claim of competitor performance, current live model quality, or public release readiness. Only this document was written; the 17-file Pages handoff remains frozen.
