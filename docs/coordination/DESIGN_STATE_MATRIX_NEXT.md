# Next Rivune design: real state matrix

2026-09-10. Source-derived design requirements for the sole app builder. This is a mapping and design acceptance brief, not a production change, external design submission, or native verification. Keep Tauri, the silver-orbit Rivune identity, a peripheral galaxy, chat-first hierarchy and real Constellation evidence. The generated design must accommodate failure and partial work as deliberately as its successful conversation screen.

Component paths below are relative to `prototypes/ai-native-workspace/src/`. Read against current host source; do not infer release status from this matrix. The prior Quiet confirmation P2 is closed and its confirmed-summary behavior must be preserved.

## Builder priorities and actionable design gaps

1. **Require adverse-state variants alongside the successful chat.** The Quiet fixture primarily demonstrates a populated conversation, explicit send, failed save, Settings and Results. Request separate designs for initial hydration failure, unconfirmed configuration, unresolved submission, partial Constellation and uncertain retry. Do not accept one success screenshot as state coverage.
2. **Give a failed empty workspace its own hierarchy.** Current no-conversation text can say “Create or choose” after hydration fails while the error is elsewhere. Preserve the error as the primary state; distinguish first use from inaccessible saved history without changing recovery authority.
3. **Allocate visible room for confirmation and recovery.** Compact composer controls must fit the wrapping last-confirmed summary, unresolved request status and recovery actions at narrow widths. Do not hide actionable uncertainty inside collapsed diagnostics.
4. **Keep participant cards evidence-driven.** Bind any redesigned cards to `run.admitted.team`, saved activity, memberResults, final answer and resolution. Include unknown model, no activity, shortened contribution, failed/cancelled and no-final variants. “Research/Review/Lead” fixture labels are synthetic, not proof that those agents or review stages ran.
5. **Treat streaming as a proposed capability, not a styling task.** Current saved-snapshot behavior is intentional. Any token animation or live progress percentage requires a separate data/lifecycle change; preserve honest activity wording in the present design.
6. **Map responsive panels before polishing.** Current Results replacement uses 1200px; sidebar navigation has a separate narrow layout. Define which surface owns focus for Chat, Conversations, Results, execution editor and native Settings. Preserve draft node, list scroll, Escape and return-focus behavior. Verify dropdown → Settings focus in the actual UI rather than relying on component-library defaults.
7. **Use human labels with optional provenance details.** Keep saved member/provider identity and exact result metadata reachable, while keeping IDs/digests outside the main answer reading path. Unknown resolved model stays unknown; completion and peer review cannot be inferred from a provider label.

## Contract guardrails for design handoff

Run/event states include queued, running, completed, failed, cancelled and uncertain; event phases include admission, direct, decide, contribute, integrate, review, final and recovery. A phase name alone is not completion evidence. Current artifact contract supports available plain text only; it has no downloadable file, executable preview, unavailable-file repair or editable document variant. Results retry, failed-step retry, save retry, reconciliation and display refresh are different actions and should not share an ambiguous “Try again” command.

Use synthetic content for generated design examples. No private draft/source upload, provider/account action, payment or external submission was performed for this mapping. User subscription access does not imply extra spending authorization. Sole builder owns production integration; final visual acceptance and native runtime proof remain separate.
