# Cancel during pending submission — 2026-09-09

The independent audit correctly found that the real host submission promise remains pending through provider execution. The controller and mounted interface shared that submission lock with Cancel. Immediate-ack mocks missed the mismatch.

This narrow fix uses the auditor's compatible fallback: cancellation has an independent lane, while the original submission remains awaited and its admission lock remains held. The host execution lifetime and reserved-submission fence are unchanged. A second send is never enabled merely to allow cancellation.

Only an exact request/conversation already present as queued/running in the durable snapshot can be cancelled. Before admission, an unknown cancellation invokes nothing and does not promise that later dispatch is impossible. Pending submissions now poll saved state even when direct execution emits no events; valid events also trigger hydration. Once the run is visible, the UI reports working and enables Cancel independently of the pending submission. Cancel has its own duplicate-click latch. Refresh uses a read-only status lane.

Rejected, malformed or failed cancellation does not claim a terminal state or release submission protection. The user can refresh/retry the same saved run. A late original submit acknowledgement or transport failure cannot itself replace the saved cancelled result. Disposing a renderer before reserve/submission completes does not dispatch a newly abandoned reservation or clear recovery from the stale renderer.

Executed validation: 87 Node tests pass, including six delayed-lifetime controller tests and two independent transient-poll recovery tests, and all 15 mounted browser scenarios pass. The mounted lifetime scenario observes a durable running record while submit remains pending, clicks enabled Cancel, verifies one submit and one exact cancel before the original promise resolves, then remounts after browser-storage loss and observes cancelled without replay. Separate cases preserve running state and block Send after rejected/failed cancellation. Eventless polling is covered in both mounted and controller tests; cancellation before admission is covered in controller tests. TypeScript/Vite build passes; final bundle `index-CIlqsbNz.js`.
