# Rivune polish acceptance

User-set goal, September 7: make the real app and download website smooth and polished, preserving the premium Rivune design. One product, one team, one lead-chosen strategy. Tests alone are not a visual or live-workflow acceptance.

| Journey | Required behavior | Current next owner/work | Acceptance evidence |
|---|---|---|---|
| Discover Rivune | Clear one-team explanation and truthful real-app imagery; mobile-readable prerequisites and preview/download state | Website task: isolated Pages visual/copy candidate | Desktop/mobile rendered checks, keyboard navigation, no overflow, real links; site21tests currently pass |

Current scope: local candidate development/review and existing isolated installation workflow remain authorized. Public publication, purchases, paid services and provider workloads outside the current preflight remain separate. The new goal does not remove known readiness requirements.

Product success includes a fresh user completing a direct conversation, a lead-directed team request and an artifact continuation without navigating technical setup repeatedly; it does not require claiming better output than Traycer without comparative evidence. Visual acceptance preserves the user's chosen background, readable dark response surface, branded controls and macOS window/security/file semantics.

Measure on an identified native build: startup to usable composer; open/switch history with a long answer; first visible streaming content when a supported provider is available; scrolling during streaming; Settings return; Stop acknowledgement and final termination state; reconnect and result recovery. Record measured timings rather than inventing a percentage-polished score or fixed delivery date. CUA helper recovery is externally blocked; do not repeatedly restart it without changed service state.

The site can publish an honest informational preview before DMG readiness; a disabled download is not a completed download experience. Cloud pricing remains a validation target; current private Plus target is19USD/month. Paid service implementation does not replace this polishing pass.

## Expanded user goal — menu-bar Review and provider consistency

ChatGPT/Codex and Claude/ClaudeCode connection choices must map to supported real routes with clear readiness, model/options, history/context and tool availability. Reuse the same Rivune composer/team/review UX, preserve drafts and files across provider changes, and disclose incompatible capabilities before a request. Actual consumer interfaces, histories, subscriptions and tools are not assumed interchangeable; exact route and live workflow evidence are required.

Menu-bar Review is an additional acceptance journey: recognizable Rivune icon in macOS menu bar, compact branded panel, real task state, open/focus the main window, draft-safe new conversation, in-app Settings and Quit, keyboard/Escape/outside dismissal, appearance/accessibility. Any review text or screenshot must be explicitly supplied and pass through the same supported conversation/team pipeline; no silent app surveillance or fake review result. The user clarification on the initial Review input action remains pending. Source/build tests cannot replace native rendered and lifecycle verification.
