# Explicit conversation connection

The composer displays whether the current conversation follows the workspace default, is pinned to a saved provider, or uses a Constellation team. A configured provider-default route can be selected and explicitly pinned using Save conversation connection. This does not change the workspace default, replace a team, discard explicit model/effort choices, or send a message. Follow workspace default explicitly clears the saved provider binding with the same durable rich-draft contract. Future sends preserve null selection and the host resolves the workspace default at admission, including later default changes. Explicit model/effort and team choices cannot be silently replaced.

The controller snapshots the expected route, catalog revision and rich-draft revision, refreshes authoritative metadata and rejects stale choices or active/pending work. Team binding requires its separate configuration flow. Existing rich-draft mutation identity, revision CAS, exact durable acknowledgement and pending-save recovery are reused. The current local draft and attachments accompany the mutation unchanged. Unknown outcomes retain pending mutation identity; replacement changes are blocked until that save is resolved. A fresh snapshot alone is not a durable acknowledgement.

Native save_rich_draft_in now rejects changed selection/team when a submission recovery record or queued/running run exists under its workspace lock. Unchanged configuration can still accompany draft-preservation saves. Existing same-mutation reconciliation remains available. Route capability/catalog validation remains host-owned; no new provider transport or admission bridge is introduced.

The controller and UI enforce stale review; native CAS and catalog checks provide the final boundary. Configuration may update visible state before an uncertain persistence result, so the UI does not claim durable success from visible state. Mutation recovery remains the existing draft-save flow; it is not an additional automatic retry. No real provider or auth operation is part of saving the selection.

Settings review corrections in the same slice: a durable provider receipt survives a subsequent display-refresh failure. A read-only Refresh workspace display action retries only controller refresh; it cannot configure again. Empty-provider instructions are conditional on the optional guarded setup capability. Synthetic selected scenarios: conversation-binding, provider-refresh, provider-empty, plus team-form compatibility.

Inherited admission resolves the current workspace default through the current catalog and defaults-only resolver under native admission. The persisted rich-draft selection remains null, legacy provider model overrides are cleared only in the admitted copy, and providerManagedDefault resolution provenance is retained. Missing/unsupported routes are rejected.
