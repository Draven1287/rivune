# Codex advertised model discovery

This optional bridge capability returns advertised metadata, not account entitlements or a dispatch catalog. It never enables model or effort selection. Existing provider-default fallback and admission checks remain authoritative. No UI auto-discovery is connected.

## Protocol basis

Investigated installed `codex-cli 0.153.4` using version/help and nonexperimental `app-server generate-json-schema`. No real discovery session was run. Official references: [app-server documentation](https://learn.chatgpt.com/docs/app-server) and [model-list implementation](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/models.rs). Main-branch documentation can change; generated installed schemas are the version-specific evidence.

Only `initialize`, `initialized`, `account/read` with `refreshToken:false`, and `model/list` with `includeHidden:false` are sent. Replies preserve picker `id`, wire `model`, and advertised reasoning strings separately. Unknown methods are unsupported; malformed core fields, duplicate IDs, cursor cycles and server-initiated requests fail closed. Additive provider fields are ignored. Partial lists are discarded on failure.

## Isolation and bounds

Unix only. The exact configured Codex executable runs as a temporary stdio child with cleared environment, scratch HOME/CODEX_HOME/cwd, file credential store, and analytics disabled. No user config, credentials or API keys are copied. Any non-null account reply aborts discovery. Other platforms/providers return unsupported. Synthetic peers verified environment isolation, fragmented output, cancellation, output-limit cleanup and child reaping. This does not prove the real executable's isolation or compatibility.

One active request globally; cancellation matches its request ID. A process-lifetime registry fences cancellation even before registration and forbids reuse after completion. It retains at most 1,024 identities without eviction or expiry; exhaustion rejects new discovery identities with DISCOVERY_IDENTITY_LIMIT until host restart. Cancellation of an unknown identity at capacity returns false, but registration also fails closed. Callers must use a fresh request ID for each attempt. Native session deadline is 8 seconds after spawn/setup, frontend timeout is 10 seconds. OS process spawn is not independently deadline-bounded. Cleanup runs in an owned worker; the command waits at most two seconds for its outcome. Timeout or worker-channel failure returns DISCOVERY_CLEANUP_PENDING, discards models and quarantines further discovery until host restart. The worker retains process/scratch ownership and may still be blocked in an OS operation; this bounds command waiting, not OS termination. It holds no host-operation/discovery lease. Quarantine prevents accumulating further cleanup workers. Nonblocking stdio prevents ordinary pipe waits; backpressure fails closed. Maximums: 1 MiB stdout, 256 KiB pending buffer, four pages of 32 entries, 128 total entries, 16 efforts/model, 32 receive iterations per reply, IDs 128 bytes, labels 256 bytes and cursors 1024 bytes. The receive-iteration bound includes the final response. Raw stderr and provider errors are not exposed.

The child owns a process group; drop kills that group, waits for the child, and attempts scratch removal. Normal-return cleanup failures produce DISCOVERY_CLEANUP_FAILED, clear any models and override a prior success/cancellation/error. No paths or OS/provider error text are included. Cleanup attempts group kill, child kill/wait and scratch deletion even if an earlier step fails. A failed deletion can leave owned scratch data; the sanitized failure makes this observable. Panic-unwind Drop remains best-effort and cannot report cleanup status. The host operation lease participates in shutdown; its provider configuration is rechecked before returning data. Admission rechecks quarantine under the registry mutex after the active lease can release it, closing the prechecked-contender race. Host finalization preserves DISCOVERY_CLEANUP_PENDING and DISCOVERY_CLEANUP_FAILED ahead of provider-change/lock-failure substitution, rebuilding those reports with no models and selection disabled. Frontend abort requests cancellation but waits for the native cleanup-aware result. A late success after abort becomes DISCOVERY_CANCELLATION_UNCONFIRMED with no models. The frontend ten-second limit returns timeout / DISCOVERY_TERMINATION_UNCONFIRMED, never a claim of completed cancellation. Cancellation observed during successful cleanup produces cancelled; cleanup failure/pending takes precedence. The cancellation fence and registration use one mutex, so either early cancellation blocks registration or cancellation signals the registered token. Finished identities remain fenced; unrelated IDs do not cancel active work. No hard OS sandbox or network prohibition is enforced by this module, and model/list may refresh provider metadata. Do not describe the capability as offline.

## Review boundary

Implemented: native transport/parser/lifecycle, typed optional bridge, sanitized states, synthetic fixtures and defaults-only separation. Unfinished: real app-server compatibility/isolation proof, authenticated entitlement mapping, executable-version negotiation, Windows transport, UI discovery controls, selection/admission integration and real provider invocation. No inference, paid call, authentication mutation, native app launch or install is part of this slice.

Next review should inspect command authorization, process isolation assumptions, identity exhaustion and cleanup-failure handling before considering any separately authorized real discovery probe. Selection must remain disabled until identity and admission are proven.
