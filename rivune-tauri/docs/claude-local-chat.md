# Claude subscription chat in the local development preview

This adapter exists only in Vite's development server on loopback port 1420. It is not a native Tauri or Swift bridge, hosted web service, API-key adapter, or release-ready provider integration.

`POST /__rivune/claude/chat` requires matching `Host` and `Origin` (`127.0.0.1:1420` or `localhost:1420`), a loopback socket, JSON content type, and `X-Rivune-Local-Chat: 1`. The body is `{prompt, history, model}`. Prompt length is limited to 12,000 characters, history to 198 entries (99 completed exchanges), aggregate history plus prompt to 48,000 characters, and request bytes to 256,000. Oversized context is rejected; it is never silently dropped. History roles are only `user` and `assistant`. Models are CLI aliases `default`, `sonnet`, `opus`, and `haiku`; this is not model discovery or a guarantee of account entitlement.

Successful responses use `application/x-ndjson`: text chunks, metadata, then done. Failures after streaming use an error event with a redacted message. Metadata inputTokens includes ordinary input plus cache creation and cache reads when reported by the CLI. This is last-request usage, not an exact conversation context capacity. The server never returns CLI session IDs, credentials, account email, raw stderr, or billing data.

Readiness requires the installed CLI to advertise all safety flags and return `loggedIn: true`, `authMethod: "claude.ai"`, `apiProvider: "firstParty"`, and personal `subscriptionType` `pro` or `max` under the same allowlisted environment and safe flags used to run the request. Only then does Connections return optional `canChat: true`. USER and LOGNAME are derived from the operating system user for keychain lookup. Failure remains unavailable, including when sandboxed keychain access prevents verification. No sign-in is initiated automatically.

Each request uses an empty temporary directory, safe mode, restricted mode, no tools, no MCP servers, disabled skills and Chrome, no user/project/local settings, disabled hooks, denied unattended permissions, and no session persistence. Environment inheritance is allowlisted to exclude API keys, proxy/provider overrides, config-directory overrides, runtime injection, and OAuth override tokens. Account authentication remains managed by the installed Claude CLI. Because [managed administrator policy takes precedence over command-line settings](https://code.claude.com/docs/en/configuration), this initial personal-account adapter refuses detected managed configuration files/directories, remote policy cache, or macOS preference domain, before running account checks. It does not bypass enterprise policy or support enterprise/Teams accounts. Prompt/history are serialized to stdin rather than shell arguments. A fresh process receives explicit history each time; no caller-supplied session can be resumed.

Only one request may run globally. A disconnected response stops its child; a three-minute deadline stops stalled execution, with SIGKILL after a one-second grace period. Output parsing is bounded. All automated tests use fixture processes and make no model or paid API calls. Live subscription prompts require an explicitly chosen connection and remain subject to the account's usage limits.

## Shared UI and verification

Connections offers **Use Claude** after verifying readiness. This explicitly selects Single AI and turns off simulation. The composer then provides Claude model aliases and chat-only permissions. Send streams a real reply with the model and usage reported by Claude. Stop, copy, retry, saved replies, and partial-output recovery are included. Retry retains the immediately previous nonempty attempt in a disclosure. Earlier failed turns can be tried in a new chat, preserving the history that followed them. Simulations cannot invoke the live retry path.

Continuation sends only completed real Claude exchanges from the current conversation, never simulated answers, other-provider replies, or unsent messages. Each request rebuilds this explicit history; it does not resume a CLI session. Attachments remain unsupported and block live Send until removed. Requests recheck account readiness before execution. Account usage is subject to the user's subscription settings; this does not promise unlimited or cost-free usage.

On September 12, 2026, browser verification completed two short real account requests: Claude remembered the word `observatory`, then returned that word to a follow-up question. The interface showed a completed provider response and reported usage. These were subscription CLI requests, not mock replies or API-key tests. Automated tests remain local fixtures. The packaged native bridge, additional providers, live Council/Swarm, and full Markdown rendering remain future work.
